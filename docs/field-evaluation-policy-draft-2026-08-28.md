# 単一機能要求の実地評価方針草案

- 状態: `pending`
- 草案日: 2026-08-28
- 採択記録: なし
- 収集開始: 未開始

この文書は、人間が採択する前の作業草案である。費用、閾値、最低標本数、層、査読者を
`semantic-guard` が選んだことにはせず、採択済み方針又は事前登録として扱わない。

## 既に置く範囲

| 項目 | 草案値 | 状態 |
| --- | --- | --- |
| 方針ID | `field-policy.single-function-operational-requests` | 候補 |
| 対象母集団 | 参加する実案件で、方針採択後に新規発生する単一機能要求 | 候補 |
| 用途 | 要求関係監査の候補経路を同じ保留標本で比較する | 候補 |
| 分析単位 | 人間が一つの機能的結果だけを要求すると確認した一件 | 候補 |
| 標本枠 | 参加案件の権限付き私有台帳へ、収集窓内に連続して到着した候補 | 候補 |
| 収集方式 | 連続取込を既定候補とし、層別抽出へ変えるなら収集開始前に固定する | 候補 |
| 保留条件 | 前向き取得、評価利用許諾、秘匿承認、未露出、重複群閉包 | 候補 |
| 除外 | 複数機能、分析単位不明、未許諾、秘匿未承認又は取消済み | 候補 |
| 校正専用 | 遡及資料、既知露出、露出不明、保留用途の許諾不足 | 候補 |
| 比較経路 | `direct_only → morphology → dependency → llm` | 現行契約に固定 |
| 主張上限 | 採択済み母集団と用途に限る。導入、人間受理、修復効果を含まない | 固定境界 |

「単一機能」は一文という意味ではない。一件が複数文でも一つの機能的結果なら候補になり、
一文でも複数の独立した結果を要求するなら除外又は分割対象になる。判断指針と裁定手続は
収集開始前に別版として固定する。

## 人間判断が残る値

| 未決定 | 所有者 | 何に必要か | 実装阻害 | 次の判断 |
| --- | --- | --- | --- | --- |
| 偽充足、偽反証、棄権の相対費用 | 評価方針所有者 | 閾値と費用加重損失 | しない。実評価を阻害 | 実務上の損害を比較し、根拠記録へ結ぶ |
| 五つの通過閾値 | 評価方針所有者 | 候補経路の通過判定 | しない。実評価を阻害 | 費用と許容危険から決める |
| 全体・正例・反例・必須層の最低標本数 | 統計設計所有者 | Wilson限界と層別判定 | しない。実評価を阻害 | 期待率、信頼水準、資源から設計する |
| 必須層と層定義 | 実務領域所有者 | 母集団内の偏り検出 | しない。収集開始を阻害 | 危険度、案件種別、表現型の候補を査読する |
| 費用損失の不確実性評価 | 統計設計所有者 | 点推定以外の判定 | しない。主張上限を制限 | 区間又は再標本化方針を採るか決める |
| 参加案件と資料所有者 | 各案件所有者 | 標本枠、許諾、秘匿 | しない。収集開始を阻害 | 参加と保存範囲を明示する |
| 二人以上の独立査読者と裁定者 | 評価運営所有者 | 盲検ラベル | しない。評価実行を阻害 | 利害関係と独立集団を確認して指名する |
| 意味重複査読者と比較台帳の権威 | 評価運営所有者 | 保留汚染防止 | しない。割当固定を阻害 | 被評価経路から独立した人間と台帳写しを固定する |

## 草案の包含条件

- 方針採択より後、定めた収集窓内に新規取得した
- 発生ID、原資料参照、改訂、取得時刻、原文ハッシュ値が一つの記録へ結ばれている
- 参加案件の所有者が `holdout_evaluation` と `derived_metrics` を明示的に許可した
- 実際に評価へ渡す伏字又は隔離済み内容が秘匿査読で承認された
- 人間査読で一つの機能的結果と判断された
- 学習、調整、試験、文書、規則・経路設計、過去モデル入力、過去取込を確認し、既知露出がない
- 完全一致、正規化一致、言換え・翻訳・抜粋を含む意味重複査読を終えた

## 草案の停止条件

次のいずれかなら保留割当を固定しない。

- 方針の採択記録がない、又は収集開始以後に採択した
- 許諾、秘匿、分析単位又は露出確認が未決定
- 比較台帳写し、重複群、代表候補が固定されていない
- 同じ重複群又は派生関係が校正と保留を跨ぐ
- 被評価モデル又は同じ候補経路を意味重複の判定器として使った
- 方針、正規化規則、要求関係規則、解析器、指示文、モデル又は用途が変更された

最後の変更は、既存保留を都合よく再利用せず、新しい評価方針、取込又は再査読の要否を
人間が判断する再評価契機である。

## 採択門

採択する人間は、未決定値を埋めた方針JSONを生成し、少なくとも次を確認する。

- 母集団、用途、分析単位、標本枠、包含・除外条件が互いに矛盾しない
- 偽充足を最も重大な誤りとして扱う費用順序と閾値に根拠がある
- 最低標本数と層が、都合のよい少数例だけで通過させない
- 参加案件の権利、秘匿、保持、取消時の連絡経路がある
- 査読者、裁定者、重複査読者の独立性と盲検手続が実行可能である
- 採択時点が収集開始より前であり、方針ID、版、ハッシュ値へ一致する外部判断記録がある

採択、差戻し、延期又は棄却は人間の判断である。この草案をリポジトリへ置いた事実、
試験の成功又は `field-sample-intake/v0` の `ready` は採択の代用にならない。
