# 実地標本の前向き取込

## 結論

`field-sample-intake/v0` は、`field-evaluation/v0` の手前で候補標本を受け、保留集合へ
入れてよいかを決定論的に再演する補助契約である。既知の文書例、試験データ、調整材料、
規則設計材料又はその派生物を、別の事例IDへ付け替えて保留標本と呼ぶことを拒む。

この契約が検査するのは、提出された取込記録の内部整合と内容拘束である。出所、本人性、
利用権、秘匿判断、時刻、意味重複査読の真実性を外部から証明せず、実務母集団における
検出性能も成立させない。

```text
人間所有の評価方針（採択前は pending）
              │ 採択が収集開始より前
              ▼
field-sample-intake/v0
  ├─ 出所・取得時点・三種の内容ハッシュ値
  ├─ 利用許諾・秘匿処理・単一機能査定
  ├─ 既知露出・派生関係・重複群
  ├─ 校正 / 保留 / 除外の群単位割当
  └─ 適格な群代表だけを旧 field case へ射影
              │ 方針・母集団・事例集合を照合
              ▼
field-evaluation/v0
```

## 旧契約を変えない理由

`field-evaluation/v0` の事例は閉形式であり、`subject_ref`、`subject_digest`、母集団、用途、
層、出所種別、`holdout` 分割だけを持つ。そこへ取込来歴を直に足すと既存資料と利用側を
破壊する。このため、新契約から既存の `build_field_case` へ一方向に射影し、旧スキーマ、
統計計算及び既存エラーを変えない。

取込資料と評価資料は、次を一致させる。

- 方針ID、版、方針ハッシュ値
- 母集団ID、用途ID、母集団ハッシュ値
- 射影された全事例と各事例ハッシュ値
- 事例集合ハッシュ値

これは二資料の内容一致であり、「その評価資料が現実にその取込工程から生成された」という
因果性又は外部真正性の証明ではない。両資料を一緒に保存し、明示的な結合検証器を使う。

## 取込記録

候補一件は少なくとも次を持つ。

| 区分 | 拘束するもの |
| --- | --- |
| 発生と取得 | 標本発生ID、原対象参照、改訂、出所種別、取得者、取得時刻 |
| 内容 | 原文、正規化文、実際の評価投入文それぞれの SHA-256、正規化プロファイル |
| 利用許諾 | 所有者参照、状態、許可用途、外部判断記録、有効期限 |
| 秘匿 | 情報区分、伏字・仮名化・隔離の処理、評価投入文ハッシュ値への承認 |
| 分析単位 | 人間による `single_function` / `multiple_functions` / `ambiguous` 査定 |
| 既知露出 | 学習、調整、試験、文書、規則・経路設計、モデル入力、開発査読の記録 |
| 派生 | 同じ取込資料内の `derived_from_refs` |
| 評価範囲 | 母集団、用途、層、旧 `field-case` の別識別子 |

生の要求本文は取込資料へ入れない。原資料は権限のある外部保管先に置き、取込資料には
不透明参照とハッシュ値だけを保存する。スキーマは未知欄を拒むため、`raw_text` のような
直書き欄を受理しない。ただし、不透明参照の値へ秘密情報を符号化する濫用までは検出しない。

## 保留適格性

候補は、記録から次の三状態へ再計算される。

| 状態 | 意味 |
| --- | --- |
| `eligible_for_holdout` | 提出記録上、前向き保留へ射影できる |
| `calibration_only` | 校正には残せるが、保留へは入れない |
| `excluded` | 許諾、秘匿又は分析単位の条件を満たさず、評価集合へ入れない |

保留へ進むには、全てが必要である。

- 方針が人間により採択され、その一致する判断記録が収集開始より前にある
- `prospective_consecutive` 又は `prospective_stratified` の収集窓内で取得した
- `holdout_evaluation` と `derived_metrics` の利用許諾が、射影時には割当固定時点まで有効である
- 秘匿査読が、実際の評価投入文ハッシュ値を承認している
- 人間査定が `single_function` である
- 方針で宣言された各必須層次元から、ちょうど一つの層を参照している
- 七つの露出確認範囲が全て記録され、状態が `no_known_exposure` である
- 完全一致、正規化一致、人間による意味重複査読が完了している

`pending` 方針、後付け採択、遡及資料、既知又は不明の露出、保留用途の許諾不足は
`calibration_only` になる。未許諾、許諾失効、秘匿未承認、複数機能又は曖昧な分析単位は
`excluded` になる。

## 重複と分割

候補は一つの `duplicate_cluster` にだけ所属し、群全体が `calibration`、`holdout` 又は
`excluded` の一つへ割り当てられる。完全ハッシュ値又は正規化ハッシュ値が同じ候補を
別群へ置くこと、派生関係を持つ候補を別群へ置くこと、同じ候補を複数群へ置くことを
検証器は拒む。

意味重複は、被評価モデル又は候補経路へ判定させない。独立した人間査読者が、校正資料、
試験データ、文書例、過去取込、規則・経路設計の各台帳写しと比較し、査読範囲と群分けを
ハッシュ値へ拘束する。機械検査はその申告の閉包と一貫性を見るだけで、未発見の言換え、翻訳、
抜粋又は提供者側の未知学習を発見したとは主張しない。

一群から旧評価契約へ射影するのは代表候補一件だけである。これにより、同じ内容の表記違いを
独立標本として水増ししない。

## `blocked` と検証失敗

`holdout_projection.status=blocked` は有効な取込資料になり得る。例えば、既知露出を正しく
記録した候補を人間が `holdout` へ割り当てても、資料はその事実を保存し、射影だけを止める。
`project_holdout_field_cases` は `ready` 以外を拒む。

`validate_field_sample_intake_evaluation` は、射影代表候補の許諾期限を評価資料の
`labels_released_at` まで再検査する。取込後に既知の期限が来た資料を、そのまま評価利用済みとして
結合することはできない。ただし、取込資料へ記録されていない取消、その時点より後の再利用、
外部許諾台帳の真正性までは検出しない。

次は低い適格性として保存せず、資料自体の検証を失敗させる。

- ハッシュ値、方針、母集団、正規化プロファイル又は割当プロトコルの差替え
- 収集窓外の取得、許諾・秘匿・単一機能・露出査読より前の割当、固定後の判断記録
- 未宣言の層参照、又は必須層次元の欠落・複数参照
- 同一発生IDから異なる原文ハッシュ値への付替え
- 候補欠落、複数群所属、代表候補欠落、完全・正規化重複の群分裂
- 未知又は循環する派生参照
- 保存済み適格性、射影又は集計の再演不一致

従って、事実上の不適格と資料破損を同じ `schema_validation_failed` 一語へ潰さない。

## 副作用のない API

```python
from semantic_guard.field_sample_intake import (
    build_field_sample_intake,
    project_holdout_field_cases,
    validate_field_sample_intake,
    validate_field_sample_intake_evaluation,
)

intake = build_field_sample_intake(...)
validate_field_sample_intake(intake)
cases = project_holdout_field_cases(intake, policy=adopted_policy)

evaluation = build_field_evaluation(cases=cases, ...)
validate_field_sample_intake_evaluation(intake, evaluation)
```

`field_sample_intake_errors` は安定した `code / location / message` を返す。利用側が分岐に
使うのは `code` と `location` であり、説明文を機械契約にしない。

スキーマは既存の取得面から読める。

```sh
uv run --locked semantic-guard schema field-sample-intake
```

これはスキーマ取得であって、候補を外部から収集する CLI 又は MCP 処理経路ではない。

## 実地作業の順序

1. [評価方針草案](field-evaluation-policy-draft-2026-08-28.md)の未決定値を人間が査読する。
2. 採択判断を方針ID、版、ハッシュ値へ結び、収集開始より前に外部記録へ残す。
3. 私有の原資料台帳と、空集合を含む比較台帳写しを固定する。
4. 新規に発生した単一機能要求だけを連続又は事前定義層別で取り込む。
5. 許諾、秘匿、分析単位、露出、意味重複を、それぞれの人間所有者が査読する。
6. 重複群を一つの分割へ割り当て、査読後に割当を固定する。
7. `ready` の代表候補だけを保留事例へ射影し、盲検ラベルと四経路予測を記録する。
8. 取込資料と評価資料を結合検証し、結果を人間が受理、差戻し又は保留する。

方針採択、実標本の利用許諾、査読者の指名、外部台帳の権威、評価結果の受理は
`semantic-guard` が決めない。

## 検証

```sh
uv run --locked python -m unittest tests.test_field_sample_intake -v
uv run --locked python -m unittest tests.test_field_evaluation -v
```

肯定経路は人工資料であり、実地標本でも性能証拠でもない。試験は、後付け採択、許諾・秘匿
不足、複数機能、既知・不明露出、比較範囲欠落、完全・正規化重複の群分裂、派生群分裂、
取得・査読・割当時刻、偽の適格性上書き、方針差替え、旧契約との事例集合不一致を反証する。

## 残る限界

- 自己申告を外部署名、信頼時刻、本人性又は法的判断へ昇格しない。
- SHA-256 から正規化の意味保存又は原資料の真正性を推論しない。
- 意味重複、派生関係、単一機能査定の完全性を保証しない。
- 外部台帳へ載らなかった標本、露出、取消、並行割当競合を発見しない。
- 私有原資料の保持、削除、失効伝播、排他的追記を実行しない。
- 収集枠の網羅性、抽出偏り、実務精度、修復効果、人間利用、運用適格性を評価しない。
